# 网站统一 AI 服务

网站管理员提供 DeepSeek 服务，注册用户无需个人 API Key。模型通过官方 API 在服务端调用，费用由配置密钥的 DeepSeek 账号承担，模型并不打包在网页或 Railway 容器中。

## 管理员操作

1. 使用已有管理员账号登录 `/account#site-ai-settings`。
2. 在“网站 AI 服务”填写 DeepSeek API Key；只在此密码输入框填写，不要提交到聊天或仓库。
3. 如果管理员已有个人连接，可主动勾选“使用我已经保存的个人 DeepSeek 连接作为网站服务”。此操作明确将该密钥用于网站成员调用；系统不会自动复用任何个人密钥。
4. 设置个人和全站每日生成尝试上限，勾选启用，点击“保存并验证网站服务”。首次保存会查询官方可用模型列表，不进行付费生成。之后可切换实际可用的模型。
5. 默认每人每天 3 次，全站每天 30 次，北京时间零点重置。个人范围 1–50、全站 1–1000，个人不能超过全站。
6. 在顶部状态查看今日全站尝试次数。可直接暂停，暂停不依赖服务商在线；已开始的调用可能继续完成。移除网站密钥会删除加密凭据，项目与生成记录保留。

每日次数是尝试上限，服务商失败也可能消耗次数，并非人民币预算。实际账单以服务商为准。全站同一时刻只运行一个生成任务；其他用户会收到稍后再试提示，不会后台排队或自动重试。

## 成员体验

注册登录后可以直接在 AI 点评、汇报共创中使用。发起前显示使用材料、网站付费说明和个人剩余额度。全站额度用完会明确提示，不会悄悄改用个人密钥。网站暂停或移除后，主动保存过个人连接的成员仍可使用自己的连接，并显示个人付费说明。未配置个人连接的成员显示网站服务待开启。

## 数据保护与持久化

管理接口 `/api/admin/ai` 根据实际登录会话验证管理员权限，拒绝跨站写入。外部伪造身份请求头不会授予权限。网站密钥 AES-256-GCM 加密保存在 `site-ai/ai/connection.json`，使用独立的关联数据，不能移用其他用户密文。管理员读取时只得到密钥遮罩，普通成员连遮罩也无法读取。

主密钥、SQLite 数据库、统一服务设置和额度计数均在 Railway `/data` 持久卷。保留该卷和主密钥。不要直接轮换主密钥或改成多副本；当前存储和额度设计针对单副本 SQLite。密钥从不存入前端、项目状态、下载 HTML 或 GitHub。

## 验证

自动测试覆盖管理员权限、跨站请求、密文隔离、显式复用、无个人密钥成员生成、重复请求、多人并发、个人和全站额度、失败释放与无自动重试、暂停删除、真实注册会话和重启持久化。DOM 检查覆盖管理员设置及普通用户点评保存流程。测试使用受控上游响应，不产生真实推理费用。管理员实际配置后仍需进行一次真实服务验证。
