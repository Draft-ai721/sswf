# 共创 · 多元设计工作台

**Railway 部署**：仓库已包含独立 Node.js 服务、Dockerfile、持久化存储和账号登录。新用户可访问 `/register` 自行注册，已有用户通过 `/login` 登录。部署说明见 [docs/railway-deploy.md](docs/railway-deploy.md)。首次部署先挂载 `/data` 卷，再设置初始化码并生成公共域名。

依据用户提供的《多元主体共创设计 AI 工作坊网站设计计划》制作。网站包含项目材料、个人汇报、示例点评与回应、预答辩、模型批注和版本档案。

## 概念生成与独立终评

首页以两个工作区组织，主导航为首页、概念生成、最终评审。概念区保留画布、可收起的设计助手、方案比较与受邀讨论，旧页面及分享链接继续可用。

最终评审可直接上传 SKP、PDF、JPG、PNG（最多三份，每份 20 MB），无需创建概念项目或填写汇报稿。也可从概念区固定版本选择一个方案，仅导入平面、体块和功能名称。作品单独保存，AI 点评与教师审查各有入口。教师通过邮箱绑定邀请访问，可定位图片或 PDF 图页、发布总评；学生在原意见下回应并补交材料。邀请撤销与到期约束原件和补交件访问。

AI 沿用网站服务及额度，明确点击后生成并保存到作品，重复请求沿用同一编号。PDF 最多提取前十页文字，并生成首页预览供支持图像的模型参考；实际读取范围由模型能力和引用标明。终评支持直接上传 SketchUp 原始 SKP，浏览器转换成功后固定结果并共享给受邀教师，支持旋转、缩放、平移和表面批注。转换失败保留原件，可在作品页重试。

画布体块视图支持空白处拖动旋转、右键或中键平移、滚轮缩放；Shift 拖动可在顶面上旋转视角。直接拖顶面继续拉伸，复位按钮恢复初始视角，切换视图保留当前会话相机。

## 画布、设计助手与六阶段过程

项目打开后进入画布与左侧设计助手组成的多元共创工作台。新建项目无需先填写项目名称、任务书或功能清单，直接添加空间、上传材料或对话即可开始。六阶段记录保留在“过程”侧栏：任务与目标、场地与使用者调研、功能与可行性核查、概念与多方案探索、方案设计与表达、评审修改与确认，无需逐项填完才能继续。学生自查与真实评审复核分开记录。

画布支持拖动、角点缩放、内联名称与面积、方案副本和撤销重做。“加一个20㎡交流区”等明确指令在本地生成预览，面积与重叠检查也在本地计算。复杂需求由网站 DeepSeek 服务生成建议。学生可查看修改前后，采用到当前方案或在独立副本试改，再用同尺度平面或体块对照。详见 [画布助手使用与验证](docs/canvas-assistant.md)。

已支持调研发现卡、图片底图坐标标记、功能面积计算与目标差额、约束依据、多方案自评比较与选择理由、设计说明、外部反馈转录及回应历史。DeepSeek 按阶段和目标生成带来源、行动与待验证条件的文字候选，学生审阅后保存，采用时解释理由；阶段内容和候选随快照归档。真实评审邀请支持教师、同伴、使用者视角，受邀账号可以针对阶段内容提问并复核。

辅助生成提供文字策略、功能组织建议、修改计划及可编辑的单层矩形空间布局草案。空间推演支持尺寸、数量、面积、最近边距、重叠与越界检查，平面及体块示意可导出 SVG；完整建筑图纸、渲染图及 BIM 模型生成不在当前范围。详见 [六阶段共创使用说明](docs/design-workflow.md)。

## 可视化资料、空间推演与定位评审

- 项目看板：文字想法、参考链接、材料缩略图、调研发现、备选方案和讨论以卡片组织，支持六阶段拖放、箭头移动、搜索和展板视图。引用原始项目记录，保持来源与更新关联。
- 空间推演：可从功能需求放置矩形，也可在主画布选择“绘制多边形”，依次点选顶点后闭合。选中多边形后拖动顶点修改轮廓，可撤销。详细布局支持调整位置和高度，面积、重叠、越界和相邻边距按实际轮廓计算。平面、轴测和固定版本保留绘制的轮廓。
- AI 布局：复用网站 DeepSeek 服务，按实际功能ID和画布生成可编辑草案，先审阅、保存候选，再解释采用理由。后端拒绝未知功能、超需求数量和越界的 AI 输出，保留原始生成数据。
- 定位评审：受邀真实参与者可针对具体备选方案或图片位置提问，列表按未解决、待复核和已完成筛选；角色、称呼、回应与复核由实际会话和授权控制。只读访问、到期和撤销继续生效。

使用与参考来源见 [可视化共创工具说明](docs/reference-improvements.md)。

## SKP 转换已启用

上传 `.skp` 后，原文件先保存在当前账户的私人云端空间。浏览器独立 Web Worker 使用 **OpenSKP 1.5.0（MIT）** 读取真实几何并生成带嵌入贴图的 GLB，再将转换结果存入同一网站。无需 SketchUp 桌面程序、SDK 授权或商业转换服务密钥，也不将文件发往其他转换商。

转换保留可解析的组件层级、实例变换、基础材质和 PNG/JPEG 贴图，输出统一为米、Y-up。网页支持旋转、平移、缩放、标准视角、全屏、下载原文件和 GLB、空间批注及相机恢复。批注同时绑定原文件 ID 与不可变转换结果 ID。

- 显示实际阶段与解析器报告的记录数量，不模拟百分比。
- 可取消、失败重试；取消后的旧任务不能覆盖新任务。
- 关闭或刷新页面会中断尚未完成的转换；原文件保留，可重试。
- 转换完成与浏览器加载成功分别显示，加载失败不会丢弃转换结果。
- 模型状态使用独立 R2 记录与条件写入，避免与汇报自动保存争抢状态版本。
- 归档快照由服务器读取当时的真实转换状态，旧档案不随之后的处理改变。

### 当前限制

上传上限 20 MB；GLB 输出上限 32 MB；ZIP 预检累计解压上限 96 MB；转换进程 120 秒超时；最多 20,000 节点、200 万独立几何三角形、400 万实例绘制三角形。以上为当前资源预算，**不表示已验证所有达到上限的模型**。

图层可见性、文字与尺寸标注、特殊样式、全部 SU 年份和大型实际学生模型仍需单独检查。不能把程序化教学示例当作上传文件的转换结果。

## 构建与数据

```sh
npm ci --ignore-scripts
npm test
npm run build
```

前端是原生 HTML/CSS/ES modules，Three.js 0.160.1。Railway 构建命令为 `npm run build:railway`，启动命令为 `npm start`。原 `npm run build` 保留 Sites Worker 构建用途。构建使用 esbuild 将独立转换 Worker 和网站资源打包进 Cloudflare Worker，线上不依赖脚本 CDN。许可证位于 `src/vendor/`。

运行时使用 R2 `BUCKET`。项目状态位于 `users/<userId>/state.json`，原文件在同一用户目录的 `files/<id>`，模型状态与输出位于 `models/<fileId>/`。服务器对每次读取与写入使用平台登录身份隔离；跨站写入受检；阶段快照不可由普通编辑覆盖。

API：

- `GET /api/state` / `PUT /api/state`：ETag 条件保存。
- `POST /api/files?name=...&project=...` / `GET /api/files/:id`：原文件上传与下载。
- `GET /api/models/:id`：持久化转换状态。
- `POST /api/models/:id/retry`：创建转换任务，已有成功结果时返回原结果。
- `POST /api/models/:id/progress` / `cancel`：按任务 ID 更新或取消。
- `PUT /api/models/:id/complete`：校验任务、源文件摘要和 GLB，保存不可变结果。
- `GET /api/models/:id/results/:resultId`：有所有权校验的 GLB 下载。
- `POST /api/snapshots`：保存阶段快照及服务器确认的模型状态。
